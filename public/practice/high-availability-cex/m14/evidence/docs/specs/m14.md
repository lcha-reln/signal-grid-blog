# M14 — same-apply accountable output, durable resume and bounded publication

Contract plan version: `0.17`. Predecessor: immutable `course/m13-complete`
at `eb1b65d2ea2159ba607e3271f0bfd209ea4906ea`.

This is the frozen M14 contract. Q1 adds one complexity: resumable business output from an
explicit genesis. It preserves M13 matching, routing, identity and recovery semantics. The
`matching-core` Git tree must remain identical to the predecessor. No product release belongs
to this unit; candidate M15 retains the `matching-1.0.0` operational qualification stop point.

## 1. Frozen inputs and qualification scope

The authoritative profile is `matching-testkit/src/test/resources/m14/profile-q1.json`, schema
`schemas/matching.m14.profile.v1.schema.json`. Its exact canonical UTF-8 bytes have SHA-256
`02ef0ee44900e1a472fea03ed5cb406215550994826b53f4b708e33815c6be9d`.
The file is a flat JSON object with lexicographically sorted ASCII keys, no insignificant
whitespace, decimal integer values, and one final LF. Profile hash covers that LF. The profile
contains no self-referential hash field. Its schema rejects unknown/missing fields and requires
every exact value. Startup and recovery validate both its bytes/hash and actual values. A member,
publisher, sink or launcher cannot override a limit while retaining the same profile identity.

`matching-testkit/src/test/resources/m14/workload-v1.json` freezes 12 local cases, seven real
process witnesses, seed 6414, 48 histories of 80 logical generated actions (3,840 total), and
eight semantic mutants. A logical action may expand into multiple primitive business/control
attempts; reports count both separately and cannot call a primitive an extra generated action.
The companion process protocol freezes barriers, message layouts and fault observations.

This is finite qualification of Q1 on two independent three-member localhost groups, with
external publisher and durable protocol-test sink JVMs. It is not Counter, settlement, customer
authorization, network exactly-once, unbounded historical replay, steady-state total memory,
throughput/latency/SLO, cross-host loss, cold backup or mixed-version upgrade qualification.

snapshot scope is `WHOLE_SHARD`. Execution retention policy is `ACKED_WHOLE_BATCH_ONLY`, Market
policy `BOUNDED_WHOLE_BATCH_RING`, genesis policy `M13_EMPTY_RESTING_BOOKS_ONLY`. Initial next
stream sequence is 1, acknowledged sequence and publisher epoch are 0. All these values are in
the canonical profile. The runtime's initial control revision is 0.

Qualification must trigger **actual candidate refusal** at pending Execution count 32, encoded
Execution bytes 262,144, and batch record limit 256 using this same Q1 profile. It also observes
the actual Market ring gap and transport segmentation. Large safety decoder limits, maximum
historical operation count, 512 MiB snapshot ceiling and every possible allocation ceiling need
negative validation but are not all claimed to be reached by valid business input. A report must
distinguish configured limits, observed high-water marks, and boundaries actually exercised.

M13's retained identity limit of 2,000,000 and decoder guards remain. M14 successful operation
history and terminal attribution are retained; controls do not bypass the separate historical
operation guard. At that guard, a new business/control request returns HISTORY_LIMIT without
mutation; exact prior retries remain readable. This is an explicit finite service stop, not an
indefinite drain guarantee. Full-history memory, disk and restore work remain disclosed costs.

The new runtime and protocol classes live in `matching-cluster-runtime`. The only typed result
seam added below it is in `matching-local-runtime`; no code or dependency enters matching-core.

`M14AppliedView` is deeply immutable, including nested collections and bytes. It contains genesis,
profile hash, shard, source business cut, control revision, both grants/ACKs/floors/tips/retained
encoded batches and one complete Market snapshot. After one entire replicated transition or
restore, the callback installs this view with one AtomicReference set. An external adapter takes
one reference and invokes pure `read`; it never observes mutable books or directly submits work.
No socket I/O, disk I/O, external ACK wait or thread join is added to the matching callback.

The infrastructure-free typed adapter result is a sealed union with three variants, each carrying
the unchanged `CanonicalResult` and the actual typed core batch produced by that same execution:
`Execution(ExecutionBatch)`, `Control(MarketControlBatch)`, and `MassCancellation(MassCancelBatch)`.
`DeterministicMatchingAdapter.applyTyped(M08Command)` returns it. Existing `apply` executes once
through that path and returns its canonical component. M13 exposes an opt-in typed submission
path while retaining byte-identical existing `submit`, request/response/snapshot codecs and goldens.
No string parsing, reflection, `toString()` protocol or second live execution substitutes for it.

A package-private copy of trusted installed M13 state may stage a candidate by restoring typed
book images and copying retained identity/cursor/route values. This is not a public unchecked
restore of external bytes. Public restore still reconstructs and validates the retained prefix.

Raw ingress recognizes the existing M13 request magic separately. In M14 it calls only
`submitLegacyRetry`: an exact imported M13 identity returns the original M13 replay response with
unchanged M13 wire encoding. Unknown identities are rejected `M14_LEGACY_NEW_REQUEST_FORBIDDEN`;
the old protocol never admits a new account-less order. M14 wrapper ingress can also express an
exact imported retry with absent accountRef. Downstream 512-byte read metadata requests are a
different protocol and cannot contain a 2 MiB ingress request or a 16 MiB legacy result.

## 4. Output genesis, ownership and identity precedence

`M14OutputGenesis` fields in canonical order are deployment UUID, positive shard ID, profile hash,
imported canonical M13 snapshot hash, imported M13 semantic digest, imported identity-table digest,
imported next shard sequence, imported active route version and hash. Its genesis ID is the hash
of its complete canonical bytes. It is supplied explicitly at startup, persisted and compared
against the expected deployment on recovery; restarting does not create another genesis.

Import validates the complete M13 snapshot/replayed prefix first. All resting books must be empty,
book count must fit Q1, and the complete initial M14 image must fit its decoder bound. Terminal
order identities, prepared/active rule state, mode, application/acceptance counters, original full
results, producer bindings and route remain unchanged. No account bootstrap dictionary can waive
the empty-resting-book requirement. Prior M13 facts are outside this output stream; they are never
backfilled, attributed to a default account or presented as a recoverable Execution prefix.

New Place requires opaque accountRef of 1–64 UTF-8 bytes without ISO control code points
U+0000–U+001F or U+007F–U+009F (`Character.isISOControl`).
No normalization, case conversion or aliasing to producer, operator, STP group or order ID occurs.
Other new commands require absent accountRef. New durable identity binds source M13 identity
payload and account presence/value under domain `M14_IDENTITY_V1`, as well as exact genesis.
Source UUID/slot retain M13 bidirectional identity semantics; correlation remains excluded.

Ownership is recorded only for an actually Accepted M14 order, keyed by instrument/orderId, and
retained after terminal completion. A rejected duplicate order cannot replace the owner. Trades
take maker ownership from the accepted maker and taker ownership from that taker; cancel, IOC,
STP and MassCancel dispositions use affected-order ownership. A control operator is not an owner.
Place rejection may identify its attempted request account but has no implied release. A missing
cancel has no affected owner. This records upstream-supplied attribution, not account authorization.

Admission order is canonical/genesis/shard validation, existing UUID/slot identity resolution,
then current route/producer fencing, new Q1 request shape and candidate capacity. An exact M14
retry returns its original full source response and output identities before checking current
route, fence or full queue; evicted output does not generate a new batch. Changed attribution is
an identity conflict. Imported legacy identity requires absent accountRef and exact old source
payload/slot; return original M13 replay semantics, no output references and no attribution.
Any supplied account for it yields LEGACY_ATTRIBUTION_FORBIDDEN. An unknown identity with absent
account is not reclassified as legacy. Conflicting source identity preserves M13 conflict reasons.

## 5. Two typed streams and public snapshot

Both stream identities are `(genesisId, shardId, kind)`, where kind is Execution or Market. The
subscriber validates the entire shard stream before instrument filtering. Book sequence, shard
sequence, each stream sequence, control revision, publisher epoch and transport correlation are
different namespaces. No cross-shard order, atomic route activation or global snapshot cut exists.

Each newly admitted business or route command creates exactly one complete Execution batch,
including deterministic business rejection and no-account-effect control outcomes. Only preflight
refusal and duplicate create none. Market produces at most one batch for that apply, only when
there is a trade or change in its public projection. Private rejection and unchanged preparation
do not create a Market placeholder. ACK/grant controls create neither stream output.

Execution header in order: stream identity, sequence, source command UUID, M14 identity hash,
source shard sequence, optional instrument, optional book application sequence, optional canonical
source result digest, then body kind and ordered records. Route output has no instrument/book
sequence/result digest; it contains old/new route version/hash and sorted added assignments.
Other kinds retain actual ordered typed core events as defined in section 8. Output attribution
is a typed role map attached to each event, not a rewritten core event. Stable trade identity is
Execution stream identity + Execution sequence + zero-based event index; it contains no publisher
epoch. Repeated delivery preserves the entire batch bytes and content hash.

Market contains only its stream identity, sequence and ordered public records:

1. `Trade(instrument, ordinal, priceTicks, quantityLots, takerSide)`, in original trade order;
   ordinal is zero-based among Market trades in this batch.
2. `LevelSet(instrument, side, priceTicks, aggregateRemainingLots)` for changed price levels,
   including zero for deletion, sorted by instrument, numeric side code, then ascending price.
3. `BookStatus(instrument, activeMode, activeRuleVersion, activeRuleHash)` for changed status or
   newly routed local books, sorted by instrument. Prepared inactive rules are not public status.

Generate trades from typed events and levels/status from before/after typed book images. All sums
use checked integer arithmetic. Market contains no accountRef, source UUID/hash, producer/slot,
operator, private order/acceptance ID, STP group, private result digest or Execution sequence.

Market snapshot fields are stream identity, profile hash, Market cut=`nextMarketSequence-1`,
then sorted books. Each book contains instrument, active mode/rule identity, sorted bid/ask levels
as absolute price/aggregate lots. Empty books are explicit. It includes every local instrument at
one installed cut, no private fields and no historical-trade claim. A consumer installs the whole
image, then only cut+1 onward. It rejects foreign identity, bad hash, backward cut and discontinuous
suffix. Snapshot repairs current market state; it never repairs Execution or old public trades.

## 6. Atomic candidate, independent retention and no partial apply

Stage each new request against a private copy of installed business/ownership/output state. Run
the actual typed matching operation, construct canonical output, snapshot projection and exact
encoded sizes, and evaluate every affected Q1 bound using checked arithmetic. Capacity is decided
from these actual bytes, not a guessed event count or later network offer.

Any book, resting-order, per-batch records/bytes, public snapshot or new-request shape overflow is
OUTPUT_PROFILE_LIMIT. Pending Execution count/byte overflow is OUTPUT_BACKPRESSURED. Historical
operation exhaustion is HISTORY_LIMIT. All leave the live runtime, source/producer identity,
route/book state, ownership, original responses, cursors, output sequences and outboxes exactly
unchanged; the refused identity is unbound and may later apply after ACK. Unexpected candidate
exceptions are SYSTEM_ERROR, not semantic rejections or mutant kills.

Public aggregateRemainingLots is an exact nonnegative signed i64. A valid source command can
make a price-level sum exceed Long.MAX_VALUE even though each order's QuantityLots is valid.
This anticipated public numeric-capacity overflow is OUTPUT_PROFILE_LIMIT, detected in the
candidate, with the same complete state/identity/output immutability as any other profile refusal.
It is not SYSTEM_ERROR and must never wrap, saturate or round. The fixed corpus actually stages
Long.MAX_VALUE lots and one more lot at the same side/price, then verifies refusal. Sequence or
revision/epoch arithmetic exhaustion is separately SEQUENCE_EXHAUSTED; unexpected internal
arithmetic exceptions remain SYSTEM_ERROR. These categories are determined by the operation
whose representable domain was exhausted, not by broadly catching every ArithmeticException.

Install the whole successful candidate only after all checks pass. Its business result, request
binding, ownership, both original output references, next positions and recoverable outboxes are
one state transition. No output is externally visible before that installation. Execution evicts
whole batches only through its replicated cumulative ACK. Market evicts oldest whole batches as
necessary for its own ring limits. It never borrows Execution quota or discards pending Execution.
Grant/ACK controls are independent of pending outbox capacity, so a full output queue can drain
within the separate finite historical guard. Another shard can continue applying and publishing.

Required count witness: retain 32 small Execution batches, then refuse the next new command.
Required byte witness: preload and ACK several books of 128 makers, then retain large sweep
batches until the next actual encoded batch would exceed 262,144 bytes before count 32.
Required record witness: 128 distinct ask levels followed by a taker crossing all makers and
resting one lot yields 128 public trades + 128 ask deletions + one new bid level = 257 Market
records; refuse before installation under maxRecordsPerBatch 256. Preserve full before/after
images for each refusal. No test may lower Q1 locally to create one of these witnesses.

Publisher ID uses 1–64 ASCII bytes in U+0021–U+007E; fixed consumer IDs must match the stream. Control
UUIDs have their own namespace. Exact duplicate control payload returns its original response
before checking current revision/fence; changed payload conflicts. A successful new control,
including an idempotent current-frontier ACK under a new UUID, consumes one control revision and
retained operation, even if frontier does not move. Rejected controls consume neither. Controls
never consume business/book/output sequence. Overflow is SEQUENCE_EXHAUSTED without mutation.

Grant compares expected current epoch (0 initially), then installs publisher ID with epoch+1.
ACK requires current exact grant, fixed consumer, generated complete-batch sequence and exact
authoritative digest. It may advance cumulatively from the old frontier to N; the receiver must
have durably validated every batch through N first. The server verifies generated history and
digest; it cannot prove remote fsync. Retain current ACK digest after eviction. Same current
sequence/digest is valid no-frontier-change ACK; backward, ahead, wrong digest, foreign identity,
wrong consumer or stale grant fails. Exact successful old control retry returns its historical
response but cannot move cursor or evict again.

InstallMarketSnapshotCursor is MARKET-only, current-grant-only, with cut/digest exactly equal to
the current authoritative whole-shard snapshot. It can advance across lost Market history after
the receiver durably installs that image. A concurrent new Market apply yields SNAPSHOT_CUT_CHANGED
and the consumer retries with the new snapshot. Its ACK digest is the snapshot digest, tagged as
snapshot rather than batch in persisted cursor state. Execution can never use this control.

Read returns a contiguous whole-batch prefix after the requested cursor, bounded by the requested
positive page limits and Q1. No read/send changes durable ACK. AfterSequence above tip is rejected.
Behind floor-1 returns EXECUTION_GAP_UNRECOVERABLE with no skip, or MARKET_SNAPSHOT_REQUIRED with
the complete snapshot. Wrong genesis/shard/kind/consumer or stale expected grant fails. Ordinary
empty-at-tip is OK with an empty page. Metadata contains grant/floor/tip/control cut; publisher
transports each page batch separately, followed by bounded terminal metadata.
If a nonempty next batch cannot fit the caller's smaller maxBytes, return
BATCH_EXCEEDS_READ_BUDGET without returning partial bytes or advancing a cursor. A successful
read always contains the current grant; a rejection before any grant exists has absent grant.
Read-response metadata encodes grant as u8 presence: 0 contains no publisher or epoch bytes;
1 is followed by publisher string then epoch i64. Initial ungranted or invalid-stream rejection
uses absence, never a synthetic publisher or epoch pretending to be authority. The same option
encoding is used by the pure API, adapter metadata and downstream response decoder.

Runtime grant does not atomically authorize a remote consumer. The controller first commits the
grant, observes it on all live replicas, then installs that exact identity and receipt hash through
the sink's inherited trusted ADMIN stdin pipe. Sink persists it before ADMIN_OK. New publisher
DATA is released after ADMIN_OK; this is the qualified external takeover boundary. DATA cannot
install any epoch, and read-adapter metadata alone is not an authorization channel. Old publisher
must remain alive and actually attempt delayed DATA and a new stale ACK after this boundary.

Sink checks trusted grant before even duplicate delivery. Complete same-sequence/same-byte data
is duplicate; changed content or a future sequence is rejected. A transaction containing complete
payload, prior/new frontier and current grant is appended and forced before ACK. Restart validates
the journal and reconstructs frontier/grants/public view; only an incomplete terminal transaction
may be discarded as torn tail, never an invalid complete or middle record. Sink is a protocol
test consumer; receipt hashes are not signatures, and local trusted ADMIN is not production auth.

## 8. Canonical encoding and stable codes

M14 binary objects start with four-byte magic and four-byte version 1, both big-endian. Magics:
command `0x4D313451`, command response `0x4D313452`, genesis `0x4D313447`, Execution batch
`0x4D313445`, Market batch `0x4D31344D`, public snapshot `0x4D313450`, runtime snapshot
`0x4D313453`, control request `0x4D313443`, control response `0x4D313441`. Profile uses its
canonical JSON, not a binary magic. Frame/read metadata use the separately frozen process protocol.

`u8` is one unsigned byte; enum codes below are u8. `i32` and `i64` are signed big-endian integers;
lengths/counts are nonnegative i32 checked against the enclosing bound before allocation. Strings
are i32 byte length plus strict UTF-8, never replacement decoding. Hash is exactly 32 raw SHA-256
bytes, displayed as 64 lowercase hex only in JSON/API. UUID is two i64 words, most significant
first. Optional is u8 0/1 followed by its value only when present. Byte array is i32 length plus
exact bytes. Lists are count then elements. Maps are count and strictly increasing keys; duplicates
or noncanonical order fail. All readers require exact EOF and byte-identical decode/re-encode.
Unknown codes, malformed UTF-8, inconsistent fields and integer overflow fail closed.

`M14StreamIdentity` encodes genesis hash, shard i64, kind. Batch identity adds sequence i64 and
content hash. Publisher grant encodes publisher string then epoch i64. Rule identity encodes
version i64 then 32-byte content hash. Core numeric wrappers use their underlying i64 and validate
the same positivity/nonnegativity constraints as the immutable predecessor. Core enum codes are
explicit below; Java ordinal is not the wire value.

of that object. Its contentHash is that trailer, without hashing the trailer recursively.

The M14 durable request identity hash is SHA-256 of the length-prefixed UTF-8 domain
`M14_IDENTITY_V1`, genesis hash, the 32 raw bytes of the source M13 payloadHash, then account
presence/value using the optional-string encoding. The source UUID/slot are bound separately as
in M13. Neither correlation nor publisher epoch enters this hash. An imported retry uses its
original M13 payload hash for lookup and is never rehashed into a conflicting new identity.

Transport's payload SHA-256 covers the entire transmitted canonical object, including its digest
trailer. Thus transport payload hash and business contentHash are distinct named fields; ACK
uses the business contentHash. A frame or report must not silently substitute one for the other.

in order before the attribution map (u8 role count, sorted role code plus account string). The
record's source instrument comes from its batch header. `rule` means RuleSetIdentity; `seq`,
`order`, `price`, `lots`, quantities, group and revisions are i64. No unnamed fields are allowed.

## 9. Snapshot recovery and bounded transport

Runtime snapshot body order: canonical profile bytes, genesis bytes, original imported M13
snapshot bytes, M14 operation count and ordered operations, current M13 snapshot bytes, ownership
count and sorted `(instrument, orderId, accountRef)` entries, control revision, Execution state,
Market state, whole-shard Market snapshot bytes. BUSINESS operation contains canonical M14 request
and original M14 response bytes; CONTROL contains canonical control request and original response.
Source correlation is normalized as in M13 identity bindings. Stream state encodes kind, next
sequence, floor, ACK sequence, digest kind/optional digest, optional grant, retained batch count and
each canonical batch byte array. Initial ACK0 has NONE/no digest; all advanced frontiers have the
matching digest kind. Ownership sorts instrument then numeric orderId. Journal interleaving is
authoritative; separate unordered command/control lists are insufficient.

Validate outer length/hash/canonical form, exact expected genesis/profile, imported M13 full prefix
and empty-book origin, then replay the retained M14 operation order through the pure transitions.
Compare each original full source/control response and each original generated output identity
(which commits its complete canonical bytes), then compare final business state, ownership,
all stream/retention/cursor/grant values and public snapshot bytes. No output is sent during replay.
An early account/event/output change with recomputed checksum still fails against its bound
original response/output digest. Missing/reordered operations, forged controls, ring holes, foreign
profile/genesis, impossible ACK and inconsistent snapshot cut fail before installation. Correctly
ACK-evicted output is allowed in the final ring; replays still reconstruct its original commitment.
Recovery and candidate staging retain full-history costs; no suffix-only or constant-time claim.

The separately frozen process protocol implements actual segmentation over loopback TCP, with
short reads/writes, one in-flight reassembly per connection, inclusive frame limit and finite
deadlines. An ordinary page is up to four independent batch messages and terminal metadata, never
one unspecified giant envelope. Complete typed payload/hash validation precedes durable acceptance.

Snapshot does not enter the 256 KiB batch queue. Adapter keeps a separately bounded immutable
1 MiB public image and <=4096-byte frame workspace. Publisher holds at most one separately
bounded snapshot image; receiver allocates at most one bounded logical message per connection.
Report queue count/bytes, snapshot image count/bytes, assembly count/bytes, frame workspace,
connections and cycle work separately. Kernel socket memory, journals, retained source history
and matching state are not included in a false “total memory <=256 KiB” claim.
